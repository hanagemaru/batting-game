更新日: 2026-11-14
対象: batting-game
状態: 調査・設計段階。**ゲーム実装は未変更**。
作業ブランチ: research-real-swing-motion-20261114（mainから独立）
既存の試作: preview-aim-cursor-ab-20261109 / PR #2（現行手作業モデル、未マージ）

## 1. 結論

これまでのスイングモデルを基準に追加調整しない。
**計測済みの身体・手・バットの時系列を真上/真後ろ/打者視点で再現し、妥当な動作を先に選定する。**
バットの芯を直接指定したり、グリップと向きを独立に動かしたりしない。
接触位置・接触時間・打球判定は、確認済みの軌道をゲーム操作へリターゲットしてから再接続する。

## 3. 優先するデータモデル

時刻 t の剛体バット状態を、観測または校正された2点で記録する。

- `H(t)`: バット近位／グリップの3D座標（cm または m、**どのマーカーから校正したか明記**）。
- `T(t)`: バット遠位／ヘッドの3D座標。
- `D(t) = normalize(T(t) - H(t))`: バット軸。
- `B(s,t) = H(t) + s * D(t)`: スイートスポット/各位置の3D座標。
- `L(t) = norm(T(t) - H(t))`: 剛体長としておおむね一定か検証。
- 身体関節: 左右手首、肘、肩、胸郭、骨盤、足の各位置/角度を別途保持し、
  グリップが身体から不自然に離れないか、関節間距離が保たれるか評価。

**実測にない位置を記録済みデータとして捏造しない。**
マーカー欠損・接触時刻の不確実性・ラボ座標の校正を記録する。

### OBP からゲームへの座標変換

OBP: `(x=投手方向, y=右打者ボックス, z=上)`
現在のゲーム: `(x=右打者/三塁側, y=上, z=投手方向)`

初期候補: `(game.x, game.y, game.z) = (obp.y, obp.z, obp.x)`。
向き・ホームベース・手元位置・左打者反転を実データで検証して確定する。
バット実長と表示長を合わせ、接触点をゲーム原点に移す。

## 4. 作業順

1. **観察用データ確保**: まず非商用の内部調査用に OBP の右打者 C3D を複数取得し、
   同じ選手の試行差と別選手差を確認。利用条件と入手元・SHAを記録。
   CMU Subject124 Trial07 の原本/利用可能なBVH/FBXミラーも取得し、身体関節を再生。
2. **生データ再生**: バットと両手・胸郭を3D軌跡で表示。真上・真後ろ・打者視点で
   同じ時刻の姿勢を確認。グリップ/ヘッド/芯を異なる色で表示。
3. **品質確認**: 物理的な剛体長・マーカーの欠損・関節長・バットの向き・
   インパクト時刻の推定誤差を検証。OBP viewer の接触時刻は
   **推定値であって実測の正解ではない**ため、独立検証する。
4. **基準動作の選定**: 右打者で、打球・肩/手元・バットが自然に見える実測の
   数試行を優先。平均化すると架空の不自然なスイングを生成し得るため、
   各時刻の座標を単純平均しない。
5. **ゲーム用リターゲット**: 1つの基準動作の全期間を実測のまま再生し、
   接触時刻を t=0 に揃える。**ユーザーの指を離した後の40msは
   「最終加速部分の入力遅延」であり、構えからの実際の全動作時間とは区別**。
   コース・高さ・投手側深度ごとに、身体/バットの剛体構造を崩さない補正を設計する。
6. **検証が先・実装が後**: まず手元/ヘッド/芯とバットの全体の動作が
   納得できるか比較。物理判定とUIへの反映はその後。現行PR #2へは
   一切上書きしない。
7. **商用化可否の確定**: OBPデータを利用する場合は商用許諾を取得。
   CMUデータだけでバット姿勢が確定できない場合は、自前でバットマーカーを
   記録するか、商用許諾済みデータを別途選ぶ。非商用データの近似コピーを
   本番に移すことは前提にしない。

## 5. 合格条件（最初の提案）

- 生データのバットを再現したとき、グリップ/ヘッド/芯が1本の剛体運動として一致する。
- バットの長さが実測誤差内で一定である。
- モーション再生で、手の移動・肘と肩の相対位置が身体に対し合理的。
- 全スイング・インパクト前後の再生で、角速度・角度に不自然な跳びがない。
- ホームベース前端の打撃瞬間で、目標位置とのずれを数値表示。
  ただし「真横」を強制して身体を破綻させない。必要なら
  実測モーションに小さな剛体回転を適用して合わせる。
- 3視点で実測とゲーム用変換の重畳比較を可能にする。
- 実測の不確実性とゲーム上の誇張を区別して報告する。

## 6. 現時点の確認/未確認

**確認済み**
- OBPには打撃C3Dとバットの10マーカー、360Hzデータが存在。
- OBPのライセンスはデータ非商用・コードMIT。
- CMU Subject124 Trial07 はBaseball Swing、商用ゲーム利用条件のある公開データ。
- 従来のPR #2はmainに未マージ。

**未確認**
- OBP/CMU個別のモーションファイルを実際にダウンロードして読めるか。
- CMU試行にバット剛体用の独立マーカーが存在するか。
- 複数コースに対応した動作補正の自然さ。
- 使うデータの商用利用契約の適用範囲。

## 7. 注意点

120Hzなら40msに約5フレーム、360Hzなら約14フレームしかない。
40msを全スイング時間と誤認して実測を過度に圧縮しない。
骨格モーションだけでバットの遠位端の向きが特定できると断定しない。
測定手順の定義を確認するまで、グリップマーカーと実際の手の位置は同一視しない。
